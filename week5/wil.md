# 내용정리
frontend:
- 각 구성요소들은 component로 묶인다.
- 해당 구성 요소들은 props에 따라 같은 형식/ 다른 내용을 갖는다. + 이는 백엔드에서 데이터를 공급받는 api와 연결된다.
- event를 통하여 사용자의 입력을 인식한다.
- 어떤 요소의 경우 state를 통해 특정 상태에 따른 변화를 보여준다.

>> 이 모든 구성요소들을 설정할 때, 사용자의 입장에서 어떤 경험(UX)를 가지게 되는지 고민할 필요가 있다.

# 용어
스켈레톤: 내용을 공급 받기전 잠깐 보여주는 '형식' 이미지  
Menu: 추가로 실행할 요소를 펼쳐서 고르는 곳  
Modal: 창위의 창으로 상위 창에 포커싱을 씌움  
Disclosure: 같은 자리에서 접고 펼치며 추가 정보를 제공함  

# 질문 작성
1. 어떤 서비스의 어떤 UI를 사용했나요? 무엇을 하려고 사용했나요?  
> 유튜브의 재생목록 기능. 배경음악들을 들으며 작업할 수 있게

2. 버튼을 누르거나 항목을 선택한 뒤 무엇이 달라졌나요?
> - 재생 목록 내 영상을 클릭하면, 해당 영상 페이지로 이동한다.  
> - 재생 목록을 접었다가 펼칠 수 있다.  
> - 영상 단위로 공유 등의 추가 작업을 할 수 있다.  

3. 사용하면서 편리하거나 헷갈렸던 부분은 무엇이었나요?
> - 오늘은 듣기 부담스러운 음악을 스킵할 수 없다.  
> - 유튜브 자체 생성의 경우, 셔플, 반복의 기능도 지원해 주지 않는다.
> - 터치가 없을 경우 자동으로 끊긴다.
> - 순서를 변경 할 수 없다.

4. 그 UI가 원하는 일을 하는 데 어떤 도움을 줬나요?
> - 원하는 노래들을 한곳에 모아두고 조작이 가능하다.

5. 내가 만든다면 유지하거나 바꾸고 싶은 부분은 무엇인가요? 그 이유는 무엇인가요?
> - 특정 영상을 건너뛸 수 있게 영상 메뉴에 추가하고 싶다. 작업하는 중 켰을땐 조작을 못하는 경우가 다반사이기 때문이다.
> - 같은 이유로 개인설정에서 무입력시 언제까지 재생될 지 선택할 수 있는 옵션이 마련되었으면 한다.
